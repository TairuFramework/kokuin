Full-repo audit of kokuin (刻印, identity / auth / keys layer). Findings are grouped
by severity and ordered by priority. Each item cites `file:line`. Critical items were
re-verified against source. This is a point-in-time snapshot; line numbers may drift.

## Critical — fix before external consumers depend on this

### 1. Permission prefix match grants ancestor resources (privilege escalation)

`packages/capability/src/index.ts:244` (`hasPartsMatch`) only iterates over the
`expected` parts. When the requested permission is a path-prefix of the grant, the loop
falls off the end and returns `true`. A capability granting `res: 'foo/bar/baz'`
therefore authorizes requests on `foo/bar` and `foo`, and `act: 'test/read'` authorizes
`act: 'test'`. This affects both invocation checks (`checkCapability`) and
delegation-minting (`assertValidDelegation`, `createCapability`) — a delegate can mint
capabilities scoped *wider* than its parent.

- Fix: return `false` when `actualParts` runs out before all `expectedParts` are matched.
- Test gap: no test covers the requested-is-prefix-of-grant direction. Add one.

### 2. Firmware signs and does ECDH with zero user consent (silent signing oracle)

`sign_approved()` is called straight from the APDU handler
(`apps/ledger/src/sign_message.c:72`); ECDH has a literal
`// For now, auto-approve` (`apps/ledger/src/ecdh_x25519.c:81`). No confirmation UX
exists in the repo (`menu.c` is just `UX_INIT()`). Any local process with HID access to
an unlocked device can mint identity JWTs and decrypt JWEs silently. This defeats the
purpose of a hardware keystore and contradicts `apps/ledger/README.md:13` which claims
Confirmation = "Yes" for both flows.

- Fix: add a BAGL/NBGL approval flow before `sign_approved`/`ecdh_approved`.
- Related: firmware never resets `G_context.req_type` after signing
  (`sign_message.c`), so a bare continuation chunk is signed with the stale path —
  becomes a real consent-bypass once first-chunk-only confirmation is added.

### 3. `verifyToken` accepts `alg: none` tokens

`packages/token/src/token.ts:207` (string path) and `:171` (object path) return the
unsigned payload with attacker-chosen claims and skip `exp`/`nbf` validation entirely.
The capability layer is shielded by an `isVerifiedToken` check, but any direct consumer
that does not re-check `isSignedToken`/`mode` is spoofable.

- Fix: reject `alg:none` unless the caller explicitly opts in; document the requirement
  to check `isVerifiedToken` after `verifyToken`.

### 4. `ElectronKeyEntry.set()` destroys all other keys

`packages/electron/src/entry.ts:58` does `setKeys({ [this.#keyID]: encrypted })`, which
replaces the entire `keys` record with a single entry (`store.ts:39` writes it
wholesale). Storing a second identity irrecoverably deletes the first. `remove()`
(`entry.ts:81`) does the read-spread-write correctly; `set()` must too. Masked because
every test uses a fresh store per keyID.

### 5. Changeset fixed release group not configured

`.changeset/config.json:5` has `"fixed": []` / `"linked": []`, but AGENTS.md documents
that token, capability, browser, node, deterministic release together. Versions have
already diverged (token 0.1.1, capability 0.1.0, browser 0.1.2, node 0.1.1,
deterministic 0.1.1). Configure the `fixed` group.

## High

- **Browser `setAsync` resolves before the transaction commits.**
  `packages/browser/src/entry.ts:28` resolves on `request.onsuccess`, not
  `transaction.oncomplete`. A later abort (quota) rolls back a write the promise already
  resolved — a fresh key is handed out, the DID published, and the key never persisted →
  unrecoverable identity. Resolve on `oncomplete`, reject on `onabort`. Same pattern in
  `removeAsync`.
- **Check-then-set race in `provideAsync`.** Browser (`entry.ts:36`, separate IDB
  transactions per `getStore()`) and node (`entry.ts:67`, OS keyring) both do
  get-then-set without atomicity. Concurrent callers both see null, both generate, the
  second `set` clobbers the first → orphaned key. Use a single readwrite transaction, or
  `add()` + re-get on constraint error.
- **Explicit `kid` bypasses the `authentication` relationship.**
  `packages/token/src/did.ts:132` (`resolveKidOrAuth`) searches all of
  `verificationMethod` when a `kid` is present, so a key listed only under
  `assertionMethod` can sign tokens. The no-kid fallback correctly uses
  `authentication[0]`; the kid path must enforce the same relationship.
- **No audience validation anywhere.** `VerifyTokenOptions`
  (`packages/token/src/token.ts:27`) has no expected-audience option, and
  `checkCapability` (`packages/capability/src/index.ts:357`) never compares the
  invocation `aud` to the verifying service. A token for service A replays against B.
- **electron: no `safeStorage.isEncryptionAvailable()` check.**
  `packages/electron/src/entry.ts:8`. On Linux without a keyring, Electron silently uses
  a hardcoded-key backend → private keys plaintext-equivalent on disk, no warning.
- **`apps/ledger` firmware never built in CI.** No workflow touches it, and the Speculos
  suite auto-skips when the emulator is absent (`describe.skipIf`), so
  `turbo run test:unit` green-lights without running the APDU round-trip. C sources can
  break silently.
- **turbo: tests don't depend on build; `clean` task is dead.** `turbo.json:9` —
  `test:types`/`test:unit` have no `dependsOn` on build, so a fresh-clone `pnpm test`
  fails (types point at `lib/`). The `clean` task (`turbo.json:4`) matches no package
  script (all use `build:clean`), so `build:js`'s `^clean` dependency is a no-op.
- **No SLIP-0010 test-vector assertion.**
  `packages/deterministic/test/derivation.test.ts:26` cites "Test Vector 1" but only
  asserts key length and determinism. A wrong derivation (swapped IL/IR, wrong HMAC key)
  would still pass. Assert the vector's expected private-key hex.

## Medium

- **Host never checks protocol version.** `GET_APP_VERSION` is defined
  (`packages/ledger-device/src/apdu.ts:6`) but never called; no compat gate before
  signing. Firmware version is duplicated in `apps/ledger/Makefile:13` and
  `apps/ledger/src/constants.h:46` with nothing tying them (0.1.0 vs package 0.1.1).
- **`encodeDerivationPath` encodes garbage as `0'`.**
  `packages/ledger-device/src/apdu.ts:38` — `parseInt("abc'")` → NaN → `0x80000000`,
  deriving a wrong key silently. No `index < 2^31` range check. Deterministic HD path
  validation (`packages/deterministic/src/derivation.ts:6`) is similarly late/partial.
- **Prototype cache collisions.** node/browser stores use plain objects keyed by caller
  strings (`node/src/store.ts:44`, `browser/src/store.ts:53`); `entry('constructor')` /
  `open('__proto__')` return prototype members cast as entries. Use `Map` or
  `Object.create(null)`.
- **`createRevocationRecord` takes a `signer` but signs nothing.**
  `packages/capability/src/revocation.ts:38` — records are unauthenticated; nothing
  checks the revoker issued the revoked token. Either sign the record or drop the param.
- **Type guards throw on nullish input.** `isSignedToken(null)`
  (`packages/token/src/token.ts:84`) throws TypeError instead of returning `false`,
  propagating to `assertCapabilityToken(null)`.
- **peer:4 base58 decode DoS.** `packages/token/src/peer4.ts:102` allows an encoded doc
  up to `maxDocSize * 2` = 128 KiB → O(n²) base58 decode per inbound token. Drop the
  default `maxDocSize` to a few KiB.
- **Node `list()` eager-loads every private key** (`packages/node/src/store.ts:24`), and
  one corrupt (non-base64) credential aborts the whole call. Defer decode to first
  `get()`.
- **`AUTH_ALGORITHM` otel attribute defined, never used** (`packages/otel/src/index.ts:13`)
  — dead surface, or missing instrumentation in `token.sign`.
- **otel is undocumented and outside release policy.** Hard `workspace:^` dep of all five
  fixed-group packages, but absent from AGENTS.md, `docs/agents/architecture.md`, and
  root README; no README; no changeset group; declares an unused `@opentelemetry/api`
  dep.
- **Reusable CI workflows pinned to `@main`** (`.github/workflows/*.yml`) — kokuin CI can
  break with no commit here. Pin to a SHA or tag.
- **No LICENSE file** anywhere, despite all packages declaring `"license": "MIT"` —
  nothing ships to npm.
- **No e2e coverage for `@kokuin/node`** — the only keystore without a `tests/*` app.

## Cross-cutting themes

1. **KeyStore/KeyEntry contract is undocumented and implementations diverge.**
   `packages/token/src/keystore.ts` has zero JSDoc. HD `setAsync` throws while
   browser/node store; HD `removeAsync` is a silent no-op; null semantics differ;
   identity-provider argument order flips (browser `(keyID, store)` vs node
   `(store, keyID)`); browser yields ES256 `SigningIdentity`, node/HD yield Ed25519
   `FullIdentity` for the same keyID. This is the repo's central contract — specify it
   and reconcile the implementations.
2. **Test suites are happy-path; mocks hide the real bugs.** electron never tests two
   keys in one store (masks #4); the node mock ignores the service arg; browser `open` is
   fully mocked out; there are no adversarial-input tests anywhere (`alg:none`, tampered
   delegation chains, prefix permissions, non-hardened HD paths, non-base64 credentials).
3. **All READMEs are install-only stubs.** For an auth layer there is no security-model
   documentation — non-extractable P-256 vs raw Ed25519 in the OS keyring, the alg-none
   pitfall, aud enforcement, seed retention in memory.

## Convention adherence

Good overall. `@sozai/*` deps are correctly `catalog:` resolving to published `^`
ranges; no `any`, `interface`, or `T[]` in source. Nits: `signerId` should be `signerID`
(`packages/capability/src/index.ts:190`); the `readonly` keyword appears on type members
in `packages/token/src/keystore.ts:2` and `identity.ts:16` — decide whether the
"never `readonly`" rule covers type-literal modifiers or only class fields.

## Suggested order

1. Security fixes #1–#4 (each small and verified).
2. #5 plus turbo/CI so tests actually gate (test-depends-on-build, ledger-in-CI).
3. The KeyStore/KeyEntry contract doc and adversarial tests — which would have caught
   most of the above.
